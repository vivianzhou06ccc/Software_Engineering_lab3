# 栖居 STAY · 酒店预订系统（Lab 3 重做版）

新版采用本机 Python 3.9+、SQLite 和浏览器界面。打开浏览器即可操作，数据库与程序在本机运行。运行时无需安装第三方 Python 或 JavaScript 包。四组实验二 UML 源文件和图片在 `UML/`。

## 启动

在 VS Code 打开本目录，在集成终端运行：

```sh
./run.sh
```

默认打开 http://127.0.0.1:8765/ 。保持终端运行，按 Ctrl+C 停止。如果端口已被占用，可以用 `./run.sh --port 8766`。首次启动写入 `stay.sqlite3` 并发布从当天起 180 天的示例房态，可用 `--db 文件名.sqlite3` 启动独立数据文件。

## 从界面验收

1. 以默认顾客身份点日期框的日历图标或输入日期。查某天时点“只查一晚”，再点“查询酒店和房态”。结果直接列出匹配房型、剩余量和价格。
2. 在酒店结果卡片点“查看房型和逐日房态”。每个房型下列出各住宿日的可订余量、每间每晚价格及停售、售罄或未发布状态。选择可订房型，填写示例联系人并提交，查看成交明细。
3. 顶部切换“金陵酒店员工”。从订单工作台确认订单，或打开房态日历调整对应日期的售价、可售量和停售标记。切回顾客重新查询可以看到保存后的价格和余量。
4. 顾客在“我的订单”进入订单详情，选择“申请改单”，核对新方案差价后提交。切回员工，从工作台的待处理退改办理。
5. 员工提交临时停业申请，切换平台管理员进入“停业审批”，查看影响日期与订单，审批并登记处置记录。已批准停业影响区间内的新预订。
6. 通过平台导航访问酒店资料审核、全平台订单、统计和通知审计。酒店员工和平台可访问各自授权范围，顾客仅访问本人订单。窄窗口的导航在页面底部，宽窗口在顶部。正文使用浏览器滚轮、触控板或滚动条。

下单、审批和修改会改变本地数据。希望独立试用可另开数据文件。顾客输入应使用示例联系方式。

## 需求与实现

| 实验二原型 | 可操作入口 | 主要服务 |
| --- | --- | --- |
| 酒店查询、预订报价 | 找酒店、逐日房态、确认报价 | `catalog.py`、`orders.py` |
| 我的订单、退改申请 | 我的订单、订单详情、取消登记、改单报价与提交 | `orders.py` |
| 酒店房型、房态日历、订单工作台 | 员工导航对应入口、办理入住与退房 | `catalog.py`、`orders.py` |
| 平台资料审核、临时停业、影响清单 | 平台审核、员工停业申请、平台停业审批及处置 | `catalog.py`、`operations.py` |
| 统计查询、通知与审计 | 统计、日志、通知投递记录 | `operations.py` |

日期区间含入住日、不含退房日。查询只读，订单写入与全部住宿日占用同一事务，提交结果按顾客和请求编号保存。管理员查看全平台订单时省略联系人和电话。正常入住和退房按计划日期办理。

## 待确认政策与演示

普通启动支持登记取消申请；正式取消审批、收费、真实通知渠道、统计口径及特殊住宿处理按 Lab 1 标为待确认。要演示独立的临时政策，运行：

```sh
./run.sh --demo-policies
```

演示模式使用独立的 `stay-demo.sqlite3`，可以审批取消、验证超时 30 分钟释放库存、模拟站内通知失败并重试，并查询标明演示口径的统计值。入住率仍为占位。顶部身份切换用于课程本机演示，业务权限由服务端检查。

## 验证

```sh
python3 -m compileall -q code
cd code
python3 -m unittest discover -s tests -v
```

`code/tests/browser.cjs` 使用 Playwright 在临时数据文件中运行浏览器验收。Playwright 仅为测试依赖。如已安装 Playwright 和浏览器，可运行 `node code/tests/browser.cjs`。可用 `PLAYWRIGHT_MODULE` 指向本机 Playwright 包，用 `CHROMIUM_PATH` 指定 Chrome，并用 `STAY_SCREENSHOTS` 指定已存在的截图目录。
